## 1. Sense 是什么

**Sense — Your personal taste agent.**
懂你的品味，帮你发现值得喜欢的东西。
あなたの好みを理解し、次の「好き」を見つける。

**定位（决策 0031）**：Sense 是一层 agent 行为框架：把你的日常行为、兴趣和喜好抽象成「品味」，再把品味固定成一组会自己运行的 agent 行为。一条品味可以固定成一个**行动**（替你做一件事，如起草一封 cold email）、一个**关注**（定期看它的变化，如这个人和你们的关系）或一条**信息**（查到新的就告诉你，如偶像、电影的新闻）。下面 1.1 讲「品味」本身是什么；第 4 节闭环里 A–E 是「抽象成品味」，G 是「固定成行为」。

### 1.1 定义

**Sense 是一个人在一堆选项里认出"就是这个"的能力，以及说得出为什么。**

一张表里有一堆人，你只对一个起了"特别想聊"的念头。这个念头不是兴趣（兴趣只解释你为什么打开那张表），也不是知识（知识是表里每个人是谁）。它是在同一张表上，别人划过去、你却停下来的那一下。

sense 由四样东西构成，缺一个就不成立：

| 要素 | 是什么 | 对应品味三问 |
|---|---|---|
| 场 | 当时摆在你面前的一组选项 | 什么情况下 |
| 选择 | 你停下来的那一个 | 喜欢什么 |
| 对照 | 同一个场里你没选的那些 | （没有对照，判断就退化成兴趣） |
| 理由 | 你能说出的那句为什么 | 为什么喜欢 |

一个人说"我喜欢机制清楚的论文"不算 sense；他在十篇热门论文旁边挑了一篇冷门的、理由是机制清楚，才是。**sense 只在对比里可见。**

### 1.2 与邻近概念的区别

- **兴趣**是你看什么。平台连接器给的全是这个，所以它们不是核心（决策 0008）。
- **知识图谱**是东西和东西之间的关系：论文到作者，作者到主页，主页到表格。它是地面。
- **sense** 是你在这块地面上走的那条路，和你在哪里停下来。

Superconnector 式的体验就是 sense 在图上走路：图是公共的，谁都能爬；路是你的。Sense 的工作不是把图爬全，而是学会你走路的方式，然后替你多走几步。

### 1.3 sense 的三个层次

产品要做的，是把一个人的 sense 从第一层推到第三层：

| 层 | 叫什么 | 在哪里 | 产品里的样子 |
|---|---|---|---|
| 1 | **潜在的** | 藏在你做过的选择里：对话里你夸过谁、嫌过什么、推翻过什么；浏览记录里你反复回去的；你截下、复制的。你自己没把它说成一条判断 | 石卡、铜卡与候选属性 |
| 2 | **显性的** | 被提炼成一条带场、选择、对照、理由的判断，你看过，确认或改过 | 已确认属性；银卡与金卡 |
| 3 | **生成的** | 拿着显性的判断，到一个你还没去过的场里替你选，并且说得出为什么 | agent 卡槽出一手的结果、推荐卡、关注卡的更新 |

四步体验（第 3 节）就是三层的推进：认识你 = 从潜在层读出来；向你确认 = 变成显性；替你寻找 = 生成；理解差异 = 把生成的结果和你的真实反应对照后写回显性层。

### 1.4 "独特"指什么

独特性只有一个来源：**在同一个场里，你的选择和多数人的默认选择不一样的地方，加上你的理由。**和领域中心一样的地方不叫独特，那是基本盘。所以 benchmark 展示三件事：这个场里多数人停在哪、你停在哪、你为什么。没有分数，因为分数没有对照物（决策 0010）。

### 1.5 三个词的分工

| 词 | 指什么 | 用在哪 |
|---|---|---|
| **Sense** | 产品名；也指你的判断力本身（日文「センス」） | 品牌、CLI 名、所有对外表达 |
| **Taste** | 对 Sense 能力的解释："理解你的品味" | 定位句、功能说明 |
| **Field** | 一个场：一组可比的选项。不是"研究领域"那么大，而是"从这篇论文往外两跳能碰到的人和作品"这么大 | 引擎的工作单位 |

## 2. 问题与论点

**问题。** 一个 AI 重度用户每天留下大量高信号记录：要什么、拒绝什么、纠正什么、写了什么规则、写了什么论文和代码。这些记录比任何点击流都更能说明"你如何做选择"。但今天没有东西读它们来服务用户本人；平台推荐只看消费记录，优化停留时长，并且困在单一平台。

**论点。** 品味不是分数，是**判断**："你喜欢规则简单却产生复杂行为的系统，不喜欢开头就要学一大套规则。"这样的句子能直接指导排序，也能被一句话纠正。只要能从本地 context 里提炼出一组有证据的判断，再把一个领域整理成可排序的知识库，就能用你的判断去排序这个领域，并从排序结果里看出你的独特之处和你还没看到的东西。

**为什么本地。** context 在本机，用户的 agent 在本机，隐私边界在本机。读本地会话的工具（ai-sessions-mcp、memex）已证明可行。Sense 不需要账户和上传就能完成整个闭环。

**为什么 field。** 没有领域知识库，判断无处施展；连接 Steam 或 Netflix 只拿到消费记录，排不了序也看不出独特。先有引擎，再谈来源。

**兴趣 ≠ 品味。** 兴趣是你关心什么（AI、游戏、论文）；品味是你在其中如何选择（"喜欢规则简单却能产生复杂行为的系统"）。Sense 做后者。兴趣只划定 field 的范围。

**品味的三个问题。** 对外解释时只回答：你喜欢什么？你为什么喜欢？什么情况下你会喜欢？

## 3. 核心体验

**发现 ＋ 纠正 ＋ 记住。**

用户看到的是四步；每步在引擎里有对应环节：

| 步骤 | 用户体验 | 产物 | 引擎环节 |
|---|---|---|---|
| 1. 认识你 | 指定 field，导入论文 / 仓库 / 一部分会话，或给几件喜欢／不喜欢的作品 | 有来源的证据 | context → 证据 |
| 2. 向你确认 | 3–5 条具体判断，确认、修改或补充条件 | 你认可的判断 | sense context |
| 3. 替你寻找 | 一句需求，拿到 3 条推荐和一张页面 | 可消费的发现 ＋ 你在 field 里的位置 | KB → 排序 → 可视化 → 推荐 |
| 4. 理解差异 | "人对，但我要找会做游戏的""主题对，但太浅"；抽卡 survey 的二选一 | 判断修正，下次用上 | 纠正 → 记住 |
| 5. 替你跟着 | 在追的作品、关注的人，有新动静时补给你；"我忘了"时从上次看到的地方补起 | 更新 | G 环 |

两条示例需求走同一条闭环，只是 field 不同：

> 找我的论文，告诉我接下来该认识谁。

> 找一个今晚想玩的游戏，有探索感，但我不想再学一套复杂系统。

措辞约定：不说"校准你的品味"，说"校准它对你的理解"；不贴标签，用可以被反驳的句子。不设"先确认 N 条才能继续"的门槛。

## 4. 核心闭环（权威定义）

```
                ┌──────────────────────────────────────────────┐
                │                                              │
 context ──► sense context ──► field KB ──► 排序 ──► 可视化 ──► 推荐
 (本地优先)     (判断·代表作·     (可快速检索)   (你的透镜)  (位置·独特)  (人·作品·项目)
                 反例·关注点)                                     │
                      ▲                                           │
                      └──────────── 纠正 → 记住 ◄─────────────────┘
```

每一环的输入、输出、负责者：

| 环 | 输入 | 输出 | 由谁做 |
|---|---|---|---|
| **A. 收集 context** | 本地来源（会话、指令文件、论文、仓库、收藏）＋ field 的筛选条件 | Evidence[]（可溯源、已脱敏、带 scope） | Sense，LLM 提取 |
| **B. 提炼 sense context** | Evidence[] ＋ 已有 SenseProfile | 3–5 条 Judgment（待确认）、exemplars、anti-exemplars、focus、pending_questions | Sense 提出，用户确认 |
| **C. 建 field KB** | Field 的 seeds（由 sense context 派生）＋ 启用的来源 ＋ 预算 | Item[]（去重、嵌入、带来源链）、Person[] | Sense 的扩展循环 |
| **D. 排序** | KB ＋ SenseContext ＋ Request | Ranking[]（内部分数 ＋ 对外理由） | 两阶段：检索 → LLM 逐条判定 |
| **E. 卡片与口袋** | 各入口进来的东西 ＋ Ranking[] ＋ 属性 | Card[]（七种、四个品级）、口袋、卡槽结算、融合、委托、抽卡 survey（7.5） | Sense 生成，app 呈现 |
| **F. 推荐、纠正、记住** | Ranking[] ＋ 用户反应 | Recommendation[]、Correction[] → Judgment 新版本 → 影响 C 的下次扩展与 D 的下次排序 | 用户 ＋ Sense |

| **G. 跟踪与整理** | 铜以上的关注卡、人物卡 ＋ 口袋 | 更新、归档、门槛调整、融合提示、委托（7.8） | Sense 定期执行 |

闭环只有一个；field 可以有多个；SenseProfile 跨 field 只有一个（判断带 domains，field 声明自己用哪些 domains）。

## 5. 形态（权威定义）

### 5.1 结论

Sense 是**住在你机器上的一个程序**。v1.2 起主面是口袋 app（决策 0018，修订 0013 的"两个面"）：

| 面 | 是什么 | 给谁 |
|---|---|---|
| **口袋 app（macOS，Tauri v2，决策 0020）** | 卡与收藏：Sense 页、口袋、检索、截图即建卡（截图键默认 ⌃⇧⌘A，或收剪贴板里的截图，0029）、剪贴板、七种卡面、agent 卡槽、融合、委托、抽卡 survey（7.5）；Rust 薄壳负责热键、截图、菜单栏、读本机浏览器履历；口袋状态写到 `~/Library/Application Support/Sense/pocket-state.json` | 用户本人，每天用 |
| **iOS** | v1 只走分享菜单，把文字、截图、链接送进口袋；原生 app 在 v2 | 用户本人 |
| **`sense` CLI** | 引擎与调试面：扫描、整理、出一手、导出。`ask` 与 G 环内部跑 agent 循环 | 用户本人、开发 |
| **`sense mcp`** | stdio MCP server，v1.1，进入条件见决策 0013 | 用户正在用的 Claude Code / Codex |

M0 的手机卡片页（`m0/deck.html`）是纸面原型，不是 v1 的面。

不做账户、上传、托管。以后要托管，只是把同一个本地库搬上去。

### 5.2 Sense 是不是 agent

- 在 CLI 里，`sense build` 和 `sense ask` 是 agent：它们自己规划查询、抓取、判定相关性、决定扩展方向、生成解释。
- 在 Claude Code / Codex 里，宿主是 agent，Sense 是宿主的"sense"：工具返回数据和排序，宿主继续对话。
- 两种模式共享同一个本地库和同一套规则。
- M0–M1 期间引擎没有自己的进程：宿主 agent（Claude Code）按本文档的规则以 subagent 方式执行 A、B 环，产物是 `m0/cards.json`。CLI 是之后把这套步骤固化（决策 0014）。

### 5.3 进程与存储

```
~/.sense/
  sense.db            SQLite：profile、evidence、judgments、fields、items、rankings、corrections、history
                      ＋ FTS5 虚拟表（全文）＋ 向量表（sqlite-vec，或 LanceDB 目录，待定）
  cache/<field>/      抓取的原文（可随时清空，可重建）
  renders/<field>.html
  config.toml         来源开关、API key 引用、脱敏词典路径、排除的仓库
```

- 一个进程，按需启动，无常驻。
- 所有写入是追加事件（history），任何版本可回放。
- `sense forget --source X` 级联删除该来源派生的全部证据、判断引用和 KB 条目，并给回执。

### 5.4 LLM 与嵌入的分工

| 任务 | 用什么 | 频率 |
|---|---|---|
| 证据提取（会话 / 论文 → Evidence） | Claude，批处理 | 每次 scan |
| 判断合成（Evidence → Judgment、exemplars、pending_questions） | Claude | 每次 scan 后 |
| 相关性门（候选是否进 KB） | 嵌入相似度 ＋ 小模型二分类 | 建库时每条 |
| 契合判定（Item × Judgment → +1 / 0 / −1） | Claude，批量，只对检索出的前 N 条 | 每次 ask |
| 理由与切入点生成 | Claude | 每条推荐 |
| 纠正解释（一句话 → 对判断的操作提案） | Claude | 每次 correct |
| 嵌入 | 通过 API 的嵌入模型，可换；向量存本地 | 建库、渲染 |

MCP 工具本身不调用 LLM，只返回数据；重活都在 CLI 批处理里做。

### 5.5 CLI 命令集

```
sense init
sense scan   [--since 3m] [--project NAME] [--exclude-work] [--dry-run]     # A
sense field  new <name> --domains research,projects --seed <pdf|repo|"关键词"|@person> ...
sense confirm <field>                                                       # B
sense build  <field> [--budget 2000] [--depth 2] [--sources s2,github]      # C
sense ask    <field> "接下来该认识谁" [--kind people|works|projects]        # D + F
sense render <field> [--public]                                             # E
sense correct <rec_id> (--like|--skip|--save|--almost <label> "一句话"|--reason-wrong "一句话")
sense profile (show|edit <judgment_id>|export|history)
sense forget --source <tool|path>
sense clip ["一句话"|--screenshot]                                      # 进口袋，石卡
sense clip import                                                          # 拉入 iOS 分享菜单送来的东西
sense tidy                                                                 # G 环整理：归档、调门槛、融合提示、委托
sense catchup <card_id>                                                    # 补上从上次看到的地方到现在
sense attrs [show <attr_id>]                                               # 属性清单与它串起来的卡
sense slot <agent> (show|put <card_id> <1-5>|clear <n>)                    # agent 卡槽
sense play <agent> "周末想看点什么"                                         # 出一手
sense mcp
```

### 5.6 MCP 工具集

| 工具 | 参数 | 返回 | 对应环 |
|---|---|---|---|
| `scan_context` | since, project, dry_run | Evidence[] 摘要 | A |
| `list_fields` / `build_field` | name, seeds, sources, budget | Field 状态 | C |
| `search_field` | field, query, lens: none\|me, kind, limit | Item[] ＋ why（lens=me 时） | D |
| `get_profile` | field? | Judgment[]（含状态）、pending_questions | B |
| `confirm_judgment` | judgment_id, action: confirm\|edit\|condition\|reject, text? | 新版本 | B |
| `recommend` | field, intent, kind, state, constraints | Recommendation[3] | F |
| `correct` | rec_id 或 judgment_id, kind, label, text | 产生的 Judgment 变化 | F |
| `render` | field, public | 文件路径 | E |

宿主 agent 在会话开头调用 `get_profile` 就能拿到"上次你说……"。

## 6. 数据模型（权威定义）

字段用英文；JSON Schema 在 `schema/`。没有任何对用户展示的分数字段。

### 6.1 Evidence 证据

一句可溯源的 claim。

| 字段 | 说明 |
|---|---|
| id | |
| claim | ≤300 字，已脱敏，一句话 |
| kind | `stated`（指令文件、用户明说）/ `revealed`（会话中的行为、选择、拒绝） |
| scope | `work` / `personal` / `unknown` |
| source | { tool, ref, project }：文件路径、会话 id＋轮次、"user said"；project 可匿名化 |
| observed_at, count | 时间与出现次数 |

### 6.2 Judgment 判断（卡片模型里叫"属性"）

自然语言的品味判断，档案的基本单位。v1.2 起它在卡片模型里叫属性（7.5.3），挂在卡上；字段不变，另加 `uses`（被使用次数，见 7.5.3）。注意与"判断卡"（一种 Card，记一次决定）区分。

| 字段 | 说明 |
|---|---|
| id | |
| text | 一句话判断，用户语言 |
| scene | 场：当时摆在面前的一组选项是什么（"爱壹帆电视剧列表"、"搜 hair simulation 的结果页"） |
| choice | 选择：停下来的那一个（条目或描述） |
| contrast[] | 对照：同一个场里没选的那些。空 = 该判断只是兴趣，不能升为 confirmed |
| domains[] | `research` / `projects` / `articles` / `games` / `work` / `general` |
| condition | 适用条件："想放松的晚上"；空 = 总是 |
| status | `proposed` / `confirmed` / `edited` / `rejected` |
| evidence_ids[] | |
| weight | 内部权重，不展示；用户纠正 > 用户编辑 > 确认 > 提出 |
| previous_text, created_at, confirmed_at | 版本信息 |

### 6.3 SenseProfile 档案

全局唯一：{ version, owner, evidence[], judgments[], pending_questions[], history[] }。

- PendingQuestion：{ id, question, from_evidence_ids[], target_domain, if_yes_judgment }。跨领域推断和冲突只在这里，确认后才成为 Judgment。
- HistoryEntry：{ version, at, cause: import\|confirm\|edit\|reject\|correction, summary }。summary 是下次会话开头那句话。

### 6.4 Field 领域

| 字段 | 说明 |
|---|---|
| id, name, description | |
| domains[] | 本 field 使用哪些 domain 的判断 |
| seeds[] | { kind: paper\|repo\|keyword\|person\|url, value, from: user\|derived } |
| sources[] | 启用的远程来源 |
| budget | { max_items, max_depth } |
| last_built_at, item_count | |

### 6.5 Item 条目 与 Person 人

| 字段 | 说明 |
|---|---|
| id, field_id | |
| kind | `paper` / `article` / `project` / `post` / `person` |
| title, url, summary | summary 由来源摘要或 LLM 一句话 |
| authors[] | person item ids |
| date, source, metrics | metrics：{ citations, stars, points }，只作内部参考 |
| ingested_via | { seed_id, hop, query }：它是怎么进来的 |
| known | 是否已出现在用户的本地 context（引用、star、会话提及） |
| embedding | 向量表外键 |

Person 是 kind=person 的 Item，额外有：{ name, affiliation?, links[], work_ids[], topics[], last_active }。Person 由其作品聚合而成，不单独抓取私人信息。

### 6.6 SenseContext 透镜

查询时刻的"你"，由 profile ＋ field ＋ request 合成：

{ field_id, profile_version, judgment_ids[]（已确认或同 domain 的）, exemplar_ids[], anti_exemplar_ids[], focus[], state, constraints[], built_at }

### 6.7 Request、Ranking、Recommendation

- Request：{ id, field_id, text, intent: people\|works\|projects\|any, state, constraints[], asked_at }。state 与 constraints 由一句话解析，例："今晚想放松" / "不想学复杂系统"。
- Ranking：{ field_id, request_id, item_id, closeness, fit{ judgment_id: +1\|0\|−1 }, novelty, divergence, rank, why[] }。四个数只在内部。
- Recommendation：{ id, request_id, kind, item_id, why[]{ judgment_id, text, judgment_status }, entry_point?（人：共同点、对方近况、你能提供什么）, reaction? }。

### 6.8 Correction 纠正

{ id, target: rec_id\|judgment_id, kind: like\|skip\|save\|almost\|reason_wrong\|edit, label?, text?, effects[]{ judgment_id, op }, at }

label 枚举：`right_topic_too_shallow` / `right_genre_wrong_mood` / `right_idea_wrong_expression` / `right_person_wrong_direction` / `other`。

### 6.9 Render 渲染

{ field_id, at, profile_version, projection（2D 坐标）, center, you, neighbors, frontier, blind_spots, signature_judgment_ids[], diff_vs_previous }

## 7. 引擎规则（权威定义）

### 7.1 A · 收集 context

- 入口与来源（v1.2，决策 0018）：

作者列的入口：浏览器 history log；Codex 与 Claude 会话（包括 agent 替你做的搜索）；截屏与截图（**Sense 自带**，不是 v2）；剪贴板；平台数据；Sense 自己的 UI 操作。另加 Sense 主动的 web search。全部进口袋，进来时是石卡，你留下后成铜卡。

| 入口 | 出哪种卡 | 读法 |
|---|---|---|
| 会话日志（只取用户轮次） | 判断卡、金句卡（你自己的句子）、人物卡（你提到要联系的人） | 现有 7.1 规则；M0 v2 已验证 |
| 会话里 agent 替你做的搜索（WebSearch / WebFetch 的查询词） | 兴趣卡候选、收藏卡候选 | 只取 tool_use 输入里的查询词，不读工具输出（防注入）；和你随后在对话里认可的结果配对；权重低于你自己写的话。需要改 SENSE.md 7.1 的"不读 assistant 输出"，开这一个口子 |
| 浏览器履历与书签 | 关注卡、人物卡（反复去的主页）、收藏卡（书签）、兴趣卡 | **全部扫**（作者 2026-10-21），不按站点筛，替代 v1.1 的路径包含规则。只排除两类：别人的 profile；登录、支付、银行、医疗、签证、后台类页面。出卡用频次：同一条目跨 ≥3 周、≥5 次才成石卡；单次访问只进检索 |
| 截屏与截图（Sense 自带：全局快捷键截屏、框选文字或图片、分享菜单） | 金句卡、收藏卡；偶尔判断卡（你截了一段自己的话） | 截图先 OCR 与识别（一页漫画、一条推、一段论文），猜它挂哪张卡或哪条属性，原图删，只留文字、缩略图与来源 |
| 平台数据（邮件、GitHub star、Steam、Bilibili / YouTube 订阅、社媒关注、日历） | 人物卡、收藏卡、关注卡 | 连接器只给"你消费 / 关注 / 联系了什么"，不给理由。邮件读收发双方、主题、日期，以及你自己写的正文；别人写的正文不存、不引用。v1 先邮件和 GitHub，其余 v1.1 |
| 剪贴板（复制的那一刻 ＋ 粘贴到了哪里） | 石卡：金句、收藏；粘到 agent 里的那段是判断卡的上下文 | 见 7.1.1。来源 app 与目的 app 成对记录；粘进 Claude Code / Codex 的内容与会话日志去重，只记一次 |
| Sense 的 UI 操作（对 / 不对 / 跟 / 不跟 / catch up / 留 / 删、升为关注、点开属性） | 不出新卡；改属性的状态与用次、改卡的颜色 | 这就是 F 环的纠正来源；每个动作都带时间，算"使用" |
| web search（Sense 主动） | 关注卡和人物卡的"最近动向"，推荐卡 | 只送出条目名和人名（公众人物） |

"看 log 不看 tab"在这里落实为：判断卡只从你自己写的话来（会话日志为主，截图或复制的自己的话为辅）；浏览器履历永远不出判断卡，只出关注、收藏、人物、兴趣，这些不需要理由就能成立。


- 其余本地来源：

| 来源 | 读什么 | 不读什么 |
|---|---|---|
| 论文 | 用户指定的 PDF / LaTeX 仓库：标题、摘要、章节、引用列表 | 无 |
| 仓库 | README、提交信息、依赖清单、star 列表 | diff 与源码正文 |
| 手动 | 用户给出的喜欢 / 不喜欢的作品与一句理由 | 无 |

- 会话日志的读取范围：Claude Code `~/.claude/projects/*/*.jsonl` 中 `type == "user"` 的文本块、`timestamp`、`cwd`；Codex `~/.codex/sessions/**/*.jsonl` 的用户轮次；`CLAUDE.md` / `AGENTS.md`。不读 assistant 输出、工具输出、附件、sidechain、其他 agent 发来的消息。唯一例外：WebSearch / WebFetch 调用里的查询词。
- 浏览器履历：Chrome / Arc 的 `History` 副本与书签，只读复制后查询，只读用户本人的 profile（按 `Local State` 的 profile 名核对）。**全部扫**，路径包含规则作废；排除登录、支付、银行、医疗、签证、后台类页面。访问不等于喜欢：浏览器履历不出判断卡。
- 按 field 筛选：关键词命中 ＋ 项目勾选；`--exclude-work` 默认开（工作 profile 单独标记，用户可选入）。

#### 7.1.1 剪贴板

作者 2026-10-21："复制剪贴板里面的东西，其实都是我们的 context，可以记录下来。比如复制到了 Agent 里面，或者放到什么地方都可以记录下来。"

复制比截图更频繁，而且多一样截图没有的东西：**去向**。从哪复制、粘到哪，本身就是一次选择。从论文里复制一段粘进 Claude Code，说明这段被你拿去用了；从推特复制一句粘进备忘录，说明你想留。

| 记什么 | 怎么拿到 | 备注 |
|---|---|---|
| 内容 | macOS `NSPasteboard` 的 changeCount 轮询（约 0.5 秒），取文本、图片、文件路径、URL | 不需要特殊权限 |
| 来源 | 复制那一刻的前台 app 与窗口标题；浏览器里是页面标题 | 前台 app 不需要权限；窗口标题需要"辅助功能"或"屏幕录制"权限 |
| 去向 | 理想：监听 ⌘V 时的前台 app 与窗口标题，和最近一次复制配对。M0.5 实现（0021）：不监听按键，记复制后 10 分钟内第一个切到的 app，页面写"之后切到" | macOS 不直接告诉你粘到了哪；要靠全局按键监听，需要"辅助功能"权限。右键菜单粘贴、拖放抓不到，只能部分记录 |
| 时间 | 复制与粘贴各一个时间戳 | 复制后 10 分钟内没有粘贴 = "只复制没用"，权重最低 |

**卡怎么生成**：不是每次复制都成卡，否则口袋会被淹。规则：

- 复制后粘贴到 agent（Claude Code、Codex、Cursor、ChatGPT 网页）：记为该会话的上下文，挂到之后从这段会话里抽出的判断卡上，作为"你当时拿给 agent 看的东西"。不单独成卡。
- 复制后粘贴到笔记、备忘录、文档、聊天：成一张石卡，类别由 Sense 猜（金句 / 收藏）。
- 同一段文字或 URL 一周内复制 ≥2 次：成一张石卡，不管粘到哪。
- 其余只进本地流水（保留 14 天，用于去重和检索），不出现在口袋里。

**不记什么**（读取边界，硬规则）：

- 密码管理器与系统标记为私密的内容：pasteboard 类型含 `org.nspasteboard.ConcealedType`、`org.nspasteboard.TransientType`、`org.nspasteboard.AutoGeneratedType` 的一律跳过（1Password、Bitwarden、钥匙串都打这个标）。
- 来源或去向是终端里的 ssh / sudo 提示、密码框、支付页、银行 app 的：跳过。
- 内容匹配密钥样式、邮箱、电话、卡号、≥32 位 hex/base64 的：跳过整条，不是脱敏后保留。
- 来源是聊天、邮件 app 的内容（多半是别人写的话）：跳过。要留别人的一句话，用截图，并且它只能成金句卡，不能成判断卡。
- 用户可以设黑名单 app，以及一个"暂停 1 小时"的开关。
- 本地流水是原始记录，按第 9 节同等对待：加密存在本机，不进 KB，不进任何导出，14 天滚动删除。

**和截图的关系**：截图是"我主动要留"，复制是"我顺手用了"。截图每次都成石卡；复制按上面的规则筛。两者进同一个口袋、同一套类别和属性。

- 脱敏在读取边界完成一次，入库前再查一次，失败即阻断。规则：密钥模式表（v0.5 §8.1）、邮箱、电话、人名词典、客户名词典、家目录路径。
- 每条 Evidence ≤300 字，必须有 source。`--dry-run` 列出全部待入库证据供删除。
- 指令文件 → `stated`；会话行为 → `revealed`。两者冲突进 pending_questions。
- 来源优先级（决策 0014）：会话里用户自己写的话 ＞ 指令文件 ＞ 截图与剪贴板里你自己的话 ＞ 浏览器履历与平台数据。属性的理由和对照必须来自前三者；浏览器履历与平台数据只出关注、收藏、人物、兴趣卡，不出判断。

### 7.2 B · 提炼 sense context

- 每次 scan 后，把新 Evidence 聚类，合成**最多 5 条**新 Judgment 提案。已有判断只更新 evidence_ids，不重写文字。
- 同时产出：exemplars（用户写的、反复引用的、明说喜欢的条目）、anti-exemplars（拒绝、批评、跳过的）、focus（反复回到的问题，短语）。
- 跨 domain 的推断一律进 pending_questions。
- 确认动作：confirm / edit（改文字，保留 previous_text）/ condition（补条件）/ reject。未确认的判断可以参与排序，但理由里标注"未确认"，权重最低。

### 7.3 C · 建 field KB

- 种子派生：从 sense context 出 keyword（focus）、paper（exemplars）、person（exemplars 的作者）、repo；用户可增删。
- 来源与查询方式：

| 来源 | 取什么 | 扩展方式 |
|---|---|---|
| Semantic Scholar / OpenAlex | 论文、作者、引用与被引 | 种子论文的引用图滚雪球；关键词检索 |
| arXiv | 近期论文列表 | 关键词 |
| GitHub | 仓库、用户 | 关键词、topic、依赖图、star 者 |
| HN（Algolia）/ RSS | 文章、讨论 | 关键词 |
| web search | 补缺 | 由 focus 生成查询 |
| （v2）Steam / itch.io | 游戏、评测 | 标签、相似游戏 |

- 扩展循环：取种子 → 生成查询 → 抓取候选 → **相关性门**（与种子中心的嵌入相似度阈值 ＋ 小模型二分类）→ 去重（DOI / URL / 规范化标题）→ 入库并记录 ingested_via → 从新条目取下一跳种子，直到 max_depth 或 max_items。
- 被 anti-exemplars 或已拒绝判断覆盖的区域降低扩展优先级；被收藏的区域提高。
- `known` 标记：条目若出现在用户引用、star、会话提及中，标 known=true。
- 增量：重建只处理新种子与新来源；来源可整体删除。

### 7.4 D · 排序

两阶段，避免对整个 KB 调 LLM：

1. **检索**：用 SenseContext（exemplars ＋ judgment 文本 ＋ request 文本）做向量 ＋ FTS 混合检索，取前 N（默认 200）。
2. **判定**：对前 N 条，让 LLM 逐条对照每条适用的 Judgment 给 +1 / 0 / −1，并对 request 的 state 与 constraints 给硬过滤。

四个内部量：

| 量 | 定义 |
|---|---|
| closeness | 与 exemplars 和 focus 的向量相似度 |
| fit | Σ(judgment.weight × 判定值)，已确认判断权重高于未确认 |
| novelty | known=false 为高；已知条目默认排除，可选显示 |
| divergence | 与 field 中心的距离减去与"你"的距离：正值 = 离你近、离中心远 |

排序 = fit 主导，closeness 与 novelty 次之，divergence 用于"盲区"和"前沿"。对外只给排名 ＋ why（指向 judgment_id，标明状态）。

人的排序：Person 的分数由其作品聚合（取最高的 3 件），再加"不在你的引用图 / 关注列表"的 novelty；entry_point 由共同引用、对方最近作品、你的 exemplars 生成。

### 7.5 E · 卡片、口袋与玩法

输出不是一页报告，而是一个**口袋**：你生活里的东西变成卡，卡背后是属性（你的 sense），属性被用得多卡就升级。玩法参照《小丑牌》（Balatro）与《苏丹的游戏》（决策 0016–0019）。讨论记录见 docs/cards-v1.2-proposal.md。

#### 7.5.1 三个轴

作者 2026-10-21 的话："这两个是行为（动作）、是什么（卡的 category）和状态（卡的颜色）"。即一张卡同时有三个互不替代的轴：

| 轴 | 取值 | 谁定 |
|---|---|---|
| **类别**（卡是什么） | 判断 / 推荐 / 人物 / 关注 / 兴趣 / 金句 / 收藏（截图与书签） | 来源和内容决定，7.5.2 |
| **动作**（你对它做什么） | 每种类别一套，见 7.5.2 最后一列。归成两类：判断卡问"对不对"，其余六种问"留不留 / 跟不跟" | 类别决定动作集 |
| **品级**（卡的颜色） | 石 → 铜 → 银 → 金，见 7.5.4 | Sense 按规则升降，门槛靠调 |

- **卡**是你生活里的一个东西：一次决定、一个人、一部在追的作品、一句话、一个随手存的东西、一个网页、一次被你喜欢过的推荐。
- **属性**是卡背后的 sense：这张卡为什么在你这里。同一个属性会出现在很多卡上。
- 卡从**石**到**金**：石刚进来，铜有点在意，银关注它本身，金是一种口味、往外推荐。金卡只能由银卡融合出来（决策 0022）。金卡不会自动消失，铜卡长期没用会退场。

卡是你看得见的；属性是 Sense 维护的。原来的"判断"（场 / 选择 / 对照 / 理由，6.2）在这个模型里是**属性**的内容，数据模型里仍叫 Judgment。判断卡是另一回事：它是"你在某个时候做的一次决定"这种卡，见 7.5.2。

#### 7.5.2 七种卡

| 卡 | 是什么 | 从哪来 | 卡面 | 你能做什么 |
|---|---|---|---|---|
| **判断卡** | 你在什么时候、做什么事、下了什么决定 | 会话日志里你的原话；你截图或复制的自己的话；你在卡上答的一句 | 日期 ＋ 场合 ＋ 决定了什么（放弃了什么）＋ 一句为什么 | 对 / 不对 / 改一句 |
| **推荐卡** | Sense 之前推荐过、你点过喜欢的东西。新推荐先是石卡，你 like 或 almost 后才变铜 | Sense 的推荐 ＋ 你的 like / almost | 条目 ＋ 当时为什么推 ＋ 你当时的反应 | 再看 / 升为收藏或关注 / 其实不喜欢 |
| **人物卡** | 你联系过、高评价过、关注了、cold email 过的人 | 邮件（收发双方、主题、日期；你自己写的正文）；会话里提到的人；浏览器里反复去的个人主页；社媒关注、日历、聊天平台的联系人（v1.1） | 名字 ＋ 关系（联系过 / 关注 / 想联系）＋ 你为什么在意 ＋ 最近动向 | 跟 / 不跟 / 记一次联系 |
| **关注卡** | 长期订阅、追踪的内容：作品、系列、频道、idol | 浏览器履历里跨周反复出现的同一条目；你说"我在追" | 条目 ＋ 你追到哪 ＋ 有什么新的 | catch up / 看了 / 不追了 |
| **兴趣卡** | 和你个人兴趣有关的东西：爱好、喜欢的题材、在意的方向（"跑团""降维物理模拟""川井憲次的配乐"） | 浏览器履历；会话；截图；平台数据 | 兴趣 ＋ 相关的卡 ＋ 最近新的 | 是 / 不是我在意的 |
| **金句卡** | 一句话：你说过的、别人说你留下的 | 剪藏；会话里你自己的句子；浏览器里的引文页 | 那句话 ＋ 谁说的 ＋ 什么时候留下的 | 留 / 删 |
| **收藏卡** | 随手存的东西。两个来源合成一种卡，卡面角标区分：**截图**（你框下来的一块屏幕）和**书签**（浏览器 bookmark、会回去的网页） | 自带截图；浏览器书签；剪贴板；GitHub star | 截图：缩略图 ＋ OCR 文字 ＋ 来源。书签：标题 ＋ URL ＋ 存的时候在干什么 | 留 / 删 / 升为关注 / 打开 |

书签和截图合并为收藏卡（作者 2026-10-21："可能可以合并"）。

七种卡的卡面不同，像素图的边框和底纹不同，一眼能认出种类。品级换边框材质，见 7.5.10。

#### 7.5.3 属性

属性是 sense 本身，是一句你会说出口的话，带为什么：

- 「实装到底，发布要等我看过」——因为发布不可撤回
- 「世界不能顺着玩家」——有谜底，信任度完全不一样
- 「角色要离开我之后还在、还会变」
- 「文字要像一个具体的人写的」——不要把道理直接说出来

规则：

| 项 | 规则 |
|---|---|
| 形态 | 一句话 ＋ 一句为什么。可选：它反对的是什么（对照）。这就是第 1 节的四要素，只是不再做成一种卡 |
| 从哪来 | Sense 从判断卡里提炼（一次决定 → 一条属性）；从金句卡里提炼；从你对任何卡的"为什么"里提炼 |
| 挂在哪 | 每张卡 1–3 条属性。关注卡"来自深渊"可以挂「要有谜底的世界」；人物卡可以挂「做能在交互里跑起来的物理」 |
| 什么算"用了一次" | 举例：属性「要有谜底的世界」。你留下一张《来自深渊》的关注卡，它挂着这条属性，算一次；你 catch up 了它的新一话，算一次；你截了一张推理游戏的图，Sense 给它挂上这条，你留下了，算一次。**一句话：你每次留下、打开、跟进一张挂着这条属性的卡，就算这条属性被用了一次** |
| 状态 | 候选（Sense 提的）→ 已确认（你在某张卡上点过"对"或改过它）。只有已确认的属性能拿来融合出金卡 |
| 显示 | 卡背面列出属性；点属性能看到挂着它的所有卡。这就是"你的 sense"的页面：不是一张签名卡，而是一张属性清单，每条后面跟着它串起来的卡 |

#### 7.5.4 品级：石、铜、银、金（决策 0022）

四级不是"越来越值钱"，是**卡自己会做的事不一样**：石和铜不做事，银盯着它自己，金往外生东西。

| 品级 | 是什么 | 它自己做什么 | 怎么到这一级 | 会不会消失 |
|---|---|---|---|---|
| 石 | 刚进来，还没被你留下 | 不做事 | 任何入口（截图、复制、履历扫描、出一手的结果） | 一次都没处理过的：7 天后碎掉，进仓库的碎卡堆（截图 30 天），到期前 2 天（截图 5 天）卡面出裂纹；处理过但 7 天没再碰：归档（决策 0024） |
| 铜 | 有点在意 | 不做事 | 在石卡上点"留"，或对它做了任何正向动作；金卡推荐出来的直接是铜 | 60 天没被碰：归档（检索还能搜到） |
| 银 | 关注这件事本身 | 只盯它自己的动向，不往外推荐（见下表） | 你点「跟」，或这张铜卡被碰够了次数（门槛见下） | 你点「不跟了」退回铜；不会自动消失 |
| 金 | 一种口味 | 源源不断往外推荐，推荐出来的成铜卡 | **只能由银卡融合**：两张以上共享同一条属性的银卡融合成一张金卡（7.5.7） | 不会自动消失 |

银卡"关注它本身"在七种卡上的意思：

| 类别 | 银卡盯什么 |
|---|---|
| 关注 | 新一话、新一季、新作、更新 |
| 人物 | 他的新作、新论文、新动态 |
| 收藏 | 仓库发版、论文的新版本与被引用 |
| 兴趣 | 这个方向的新消息 |
| 推荐 | 这部作品本身的后续 |
| 判断、金句 | 你之后的会话里，照这条做的新证据或反例 |

金卡往外推荐靠的是融合时共享的那条属性：叠在它下面的几张银卡说明了这条属性的范围，推荐出来的每张铜卡都写明来自哪张金卡、哪条属性、哪几张原卡。

- **门槛只管铜升银，是调出来的，不是设出来的**（作者 2026-10-21、2026-10-22）。"碰"指：打开、放进卡槽、放进用例、抽卡里被选中或被留下。起始值 3 次。按你的行为调：你在自动升上来的银卡上点「不跟了」，门槛加 1；你在碰得还不够的铜卡上主动点「跟」，门槛减 1。范围 2 到 8，每次调都记一句"门槛从 3 调到 4，因为……"。
- 降级：银卡点「不跟了」回到铜，追踪停下。金卡点「不对」：融合拆开，原来那几张银卡回到口袋，属性的用次减一。
- 属性仍然记用次，用来排"最能代表你的几条"，但不再直接决定品级。孤立的喜欢最多到银（你在盯它），**两件你在盯的事能说出同一个为什么，才成金**。这和 1.4 的"独特 = 你的选择和默认的分岔"是同一件事。

#### 7.5.5 口袋（app 主界面）

**Sense 页（决策 0023）**：按领域放你真正在看、在听、在玩的东西：动画、漫画、小说、游戏、音乐、偶像、影视，再接研究和做东西用的。每条都带来源证据。属性和原话退到最下面的「做事的方式」。音乐和大部分作品来自桌面版的「整理品味」：本机读浏览器履历与 YouTube 观看记录，由 agent 按领域整理。整理出的条目要你「收进口袋」才成卡；跨领域的联系只作为问题。

作者 2026-10-21："做成口袋，和比较好检索的一个 UI，自带一个截图的工具，截图完了之后自动作为一个生成卡的动作。"

**口袋**是 app 的唯一主界面：所有卡都在口袋里，没有"收件箱"和"收藏夹"两个地方。石卡在口袋最上面等整理，铜卡按时间往下排，金卡固定在口袋底部的一层不会被冲走。

| 部分 | 做什么 |
|---|---|
| 口袋 | 一列卡，最新在上。顶部是今天进来的石卡（截图、剪藏、履历扫出来的），一次一张滑掉或留下。往下是铜卡。拉到底是金卡层 |
| 检索 | 一个搜索框 ＋ 三个轴的筛选：类别（七个图标）、颜色（石 / 铜 / 银 / 金）、属性（点一条属性看它串的所有卡）。全文搜卡面、OCR 文字、来源标题；时间轴按周折叠。检索结果也是卡，不是列表 |
| 截图 | 全局快捷键 → 框选屏幕任意区域 → 松手即生成一张石卡，出现在口袋顶部，带缩略图、OCR 文字、来源 app 与窗口标题。没有表单。你可以不管它，整理时再处理 |
| 自动生成 | 截图落下后 Sense 在本机做三件事：认出它是什么（一页漫画、一条推、一段论文、一个商品、一个人的主页）→ 猜类别（金句 / 收藏 / 人物 / 关注 …）→ 猜挂哪条属性或哪张已有的卡（追的那部作品的新一话就挂到那张关注卡上，不另开卡）。猜错了，你在卡上改类别或拖到另一张卡上 |
| 一键 | 石卡只有两个动作：留（变铜）/ 丢。类别和属性是 Sense 填好的，你只纠正 |

截图即建卡，这一条决定了入口的优先级：macOS 全局快捷键截图是 v1 第一个要做的入口，先于浏览器履历扫描和平台连接器。因为它是唯一一个"你想留的那一刻"就能用的入口，其他入口都是事后补的。

隐私：截图原图在识别后删除，只留缩略图（低分辨率）、OCR 文字、来源。识别在本机或经你指定的 API，截图不上传到 Sense 以外的任何地方。含密码框、支付页、聊天窗口的截图，Sense 识别到就提示"这张不建议留"，默认丢。

#### 7.5.6 agent 卡槽

每个 agent 有一排卡槽，起始 4 个，第一张金卡出现时解锁第 5 个。agent 可以有多个，每个是一套存起来的配置，例如"追番""读论文""找人聊"。

| 槽位 | 作用 | 小丑牌里的对应 |
|---|---|---|
| 左边的槽 | **约束**：先筛。放判断卡、兴趣卡，决定"只看什么、不看什么" | 加法小丑，放前面 |
| 中间的槽 | **对象**：从哪里找。放人物卡、关注卡、收藏卡，决定起点 | 出牌本身 |
| 右边的槽 | **口味**：最后排序。放金句卡、判断卡，决定"挑哪个、怎么说为什么" | 乘法小丑，放后面 |
| 第 5 槽（解锁后） | **野卡**：Sense 自己放一张你档案外的卡，专门往盲区找一条 | 小丑本身 |

同一张卡放左边和放右边效果不同：判断卡「世界不能顺着玩家」放左边，没有对抗机制的作品直接被筛掉；放右边，它们还在，只是排到后面。

**邻接效果**（第一批，之后随玩随加）：

| 组合 | 效果 |
|---|---|
| 人物卡 ＋ 右边紧挨着兴趣卡 | 找这个人在这个兴趣里的新东西，而不是他所有的动向 |
| 人物卡 ＋ 判断卡 | 起草一封 cold mail，理由用这条判断（superconnector 的最后一跳） |
| 金句卡 ＋ 任意卡 | 结果卡上的"为什么"用这句话的口吻写 |
| 关注卡 ＋ 关注卡 | 只找两部作品都沾边的东西（同一作者、同一类型、同一批粉丝在聊的） |

**出一手**：你给 agent 一句话（"周末想看点什么"），agent 带着槽里的卡去找，带回 3–5 张石卡。每张结果卡上标出它是哪张槽卡贡献的。你留下或丢掉，留下的那张，它背后那几张槽卡的属性各记一次"使用"。这算一次"碰"：**卡放在槽里被用，比放在口袋里被看，更快升银。**

#### 7.5.7 融合

你在卡上点「融合…」自己挑，或者 Sense 在整理时提示"这三张可以融合"。Sense 的提示要求卡之间至少共享一条属性；你自己挑的不要求（0033）。成金要你确认时勾上，不会自动成金（0033）。

| 投入 | 产出 | 例子 |
|---|---|---|
| 2 张以上**银卡**，确认时勾了「成金」 | 1 张金卡：以共享的属性为口味，往外推荐 | 来自深渊 ＋ 海猫都挂「有谜题和谜底」→ 金卡"有谜题和谜底的世界"，每周推几部新作 |
| 其他情况（包括银卡但没勾成金） | 合并成一张，取原卡里最高的品级，不升级 | 三张挂同一属性的铜色关注卡 → 一张铜色兴趣卡 |
| 判断卡 ＋ 金句卡（同属性） | 这条属性被确认；品级规则同上 | 「实装到底，发布要等我看过」＋ 你说过的「撤回也会留下记录」 |

融合是成金的唯一路径（决策 0022）。

融合不删原卡。原卡叠在新卡下面，点开能看到，作为证据。这条和苏丹的游戏不同，因为 Sense 的证据要可溯源。

#### 7.5.8 委托

桌面版实现（0021）：委托从口袋第一次显示它那天开始倒数；全部做完或过期后，每周由 agent 按口袋里现有的卡和已确认属性出一批新的 3 张，奖励必须是能交付的东西，不替作者发送任何消息。融合提示同样按口袋实时状态算：两张以上银卡挂着同一条已确认属性就出现，作者可以挑其中几张。

Sense 每周发一到两张委托卡，每张带格子和期限，放对的卡才能开：

| 委托 | 格子 | 期限 | 完成后 |
|---|---|---|---|
| 本周补番 | 3 张关注卡 | 7 天 | 每部出一张"上次看到哪、新的是什么"的更新 |
| 想联系一个人 | 1 张人物卡 ＋ 1 张判断卡 | 7 天 | 一封 cold mail 草稿，发不发你定 |
| 这条属性还对吗 | 1 张你最近丢掉的卡 ＋ 1 张金卡 | 3 天 | 属性被确认、改写或降级 |
| 整理口袋 | 5 张 30 天没动的铜卡 | 7 天 | 留、融合或归档 |

过期不惩罚，委托消失，下周换一张。委托的作用是让你每周有一个打开口袋的理由，而不是考核。

#### 7.5.9 抽卡做 survey

作者 2026-10-21："卡比较多的时候，可以抽卡来做 survey。"

口袋大了以后，你不会一张张翻。Sense 像小丑牌发手牌一样，从口袋里抽一手卡，每手问一个很快能答的问题。答案直接写回属性和品级。

**什么时候抽**：口袋里铜卡和银卡超过 50 张后开放；你按"抽一手"，或者作为每周委托里的一张。

**一手**：5 张，一分钟内答完。不想答这一手可以弃掉重抽一次，同小丑牌的弃牌。

**抽哪几张**（加权，不是纯随机）：

| 优先抽 | 为什么 |
|---|---|
| 挂着候选属性、还没被确认的卡 | 确认过的属性才能拿来融合出金卡 |
| 快要归档的铜卡 | 最后问一次还要不要 |
| 两条属性互相打架的卡 | 例如 M0 里"不要 mock"和"暂时 mock 一下" |
| 1 张金卡 | 对照组，看你的口味有没有变 |
| 1 张随机 | 防止只问 Sense 以为重要的 |

**问法**：

| 问法 | 抽几张 | 你做什么 | 写回什么 |
|---|---|---|---|
| 还在意吗 | 1 | 留 / 丢 | 品级升降，属性用次加减 |
| 二选一 | 2 | 挑一张更像你的，可选说一句为什么 | **对照**：被放弃的那张就是对照，你那句话就是理由。这是补齐判断四要素最快的办法，日志里最缺的就是这个 |
| 排个序 | 3 | 从左到右排 | 属性的相对权重，决定 agent 卡槽里谁放左谁放右 |
| 是同一个东西吗 | 3 | 是 / 不是 | 是：提示融合；不是：拆开属性 |
| 哪张不属于 | 4 | 挑出不一样的那张 | 属性的边界：那张为什么不算，写成属性的"不包括" |

**和门槛的关系**：survey 的结果也是7.5.4 调门槛的信号。survey 里被选中、被留下都算"碰"，会把铜卡推向银；你在 survey 里丢掉自动升上来的银卡，门槛加 1。

#### 7.5.10 卡面与感觉

- 像素卡面，七种类别各一套边框和底纹，品级换边框材质：石是灰岩、铜是铜锈、银是亮银、金是流动的金。
- 卡放进槽、结果冒分数、融合合成，都要有短动画和音效。融合的那一下要有分量。
- 口袋是手牌，agent 卡槽是牌桌，委托是摆在桌边的苏丹卡。

参照对照表：

| 游戏 | 机制 | 在 Sense 里变成 |
|---|---|---|
| 小丑牌 | 5 个小丑槽，小丑是被动修正，从左到右结算；加法在前、乘法在后，顺序改变结果；有的小丑看邻居（Blueprint 复制右边那张） | agent 的 4–5 个卡槽；槽里的卡决定 agent 这一次怎么找、怎么挑；顺序有意义；部分卡有邻接效果 |
| 小丑牌 | 每次出牌，分数从每张小丑上一跳一跳地冒出来 | 每条结果上标出它来自哪张槽卡的哪条属性："＋「要有谜底」→《来自深渊》新一话" |
| 苏丹的游戏 | 事件有格子，把人物、物品放进去按属性判定；卡分品级（铜、银、金），品级越高越强也越难拿；苏丹卡七天限时 | 委托：带格子的任务，放对的卡才能开；卡分四个品级；委托有期限 |
| 苏丹的游戏 | 卡会在事件里被消耗、转化成新卡 | 融合：几张卡合成一张更高品级的卡；原卡不删，叠在新卡下面当证据 |

#### 7.5.11 benchmark（内部）

benchmark 在内部计算（相对、有证据，决策 0010），不再做成签名卡；它喂给第 5 槽的野卡（盲区）和"你的 sense"页的属性清单：

| 项 | 计算 | 表达 |
|---|---|---|
| 中心 vs 你 | 中心 = KB 质心（或最密簇）；你 = exemplars 加权质心 | 两句话对照 |
| Sense signature | 对"你附近"与"中心附近"条目的 fit 分布差异最大的 3 条判断 | 句子 ＋ 证据 |
| 最近邻 | 按 closeness 对人 / 作品 / 项目各取 5 | 排名 ＋ 共同点 |
| 盲区 | divergence 高且 known=false 的前 10；以及 field 需要却在 context 里缺席的方向 | 排名 ＋ 一句为什么 |
| 变化 | 与上次 Render 的 you、neighbors、signature 的 diff | 一段话 |

没有标量品味分；距离与判别力只在内部。Sense map（UMAP 投影）与透镜视图保留为桌面端的第二页。

分享面（决策 0004）：`--public` 导出只放已确认属性和金卡，去掉证据来源、项目名、石卡和铜卡。

#### 7.5.12 追踪台（决策 0021，0022 修订）

一张一直在转的桌子。**银卡和金卡天生就在上面**：品级决定它在转盘上做什么，不用你勾模式。

| 放在上面的 | 做什么 | 结果去哪 |
|---|---|---|
| 银卡（自动上） | 联网查"上次看到之后"它自己的新动向；判断与金句卡改为在新会话里找证据或反例 | 挂在原卡上的更新卡（石），原卡记下新进度 |
| 金卡（自动上） | 按它的口味（融合时共享的属性）往外推荐 2 到 3 样新东西 | 直接成铜卡进口袋，写明来自哪张金卡 |
| 石卡、铜卡（你手动放） | 排进抽卡出题，问你还在不在意 | 下一手先出它；被留下算一次"碰" |
| 用例卡（你手动放） | 按用例跑一遍，例如"每月看海贼王动画进度" | 进这个座位的流水 |

- 节奏：每天、每周、每月。银卡默认每周（带 `watch.cadence: monthly` 的每月），金卡默认每周。可以单张暂停。
- 转盘上一次显示最近要跑的 8 张，其余列在下面。新上来的卡错开排期，避免一打开就连跑一串。
- 只在 app 开着时跑，每 30 秒看一次是否到期，一次只跑一个；关掉期间到期的，下次打开先补。网页版不自己转，也不联网。

#### 7.5.13 用例卡（决策 0021）

作者想让 Sense 做的事也是卡，用金边米色卡面和物件卡区分。三种来源：牌桌上的 agent、委托、作者写的一句话。用例里放卡，按「做」就真的做：派 agent 出一手、联网查进度、写一封 cold mail 草稿（不替作者发送）。完成后用到的卡记一次使用。原「委托」页并入「用例」。


#### 7.5.14 口袋上限（决策 0032）

口袋装的是注意力：留下的卡（铜、银、金）有一个总上限，在跟的银卡另有一个上限。**超了只警告，不拦任何操作。**

| | 上限 | 超了以后 |
|---|---|---|
| 留下的卡 | 30 + 5 ×（等级 − 1），可手动 ±20 | 顶栏变红，口袋页顶上提示「去整理」 |
| 在跟的银卡 | 10 +（等级 − 1），可手动 ±6 | 同上 |

石卡不算在内。缩减给 XP（融合每少一张 +10，成金再 +50；整理时归档 / 不跟 +3；碾碎石卡不给），XP 升级，升级加上限。

#### 7.5.15 手动融合与相册（决策 0033）

- 任何一张卡上（石卡也行）都能点「融合…」，自己挑两张以上的卡融合，不要求共享属性：你挑的就是证据。有石卡参与时融合出的卡至少是铜卡，石卡叠在下面不再碎。Sense 的融合建议还在，只是建议，挑选可以改。
- 融合出来的卡默认取投入里最高的品级（至少铜），不升级。确认前可以勾「成金：这是一种口味」，投入全是银卡或金卡时才能勾；勾了才成金卡、开始往外推荐。
- 融合卡像一个相册：卡面拼着原卡的图，点开能一张张翻看原来的卡（截图、封面），点哪张进哪张。
- 任何融合卡都能「拆开」，原卡回到口袋。

#### 7.5.16 通话里的 agent（决策 0034）

通话时说「我最近很喜欢 X」，它当场记一张卡（明确喜欢是铜，顺口提到是石），说到已有的卡就碰一下、加一句证据，说要盯着就开始跟。挂断后列出这通电话记了什么，可以撤销；新卡由 agent 上网核对名字后才去掉「听来的」。通话里它能上网查，链接不念。状态在桌宠脚下显示，服务卡住会自己重起重拨。

#### 7.5.17 角色的成长层（决策 0036，第一步）

正本是仓库里的 soul.md；她经历出来的东西放在本机 `characters/<id>/`（女版男版各一份），照 soul 规约分「正本」和「知识」：`knowledge.md`（关于他 / 关于世界 / 想问他的，每条带日期和渠道）、`diary/`、`opinions.md`、`stories/`（一起编的故事的设定集）。通话全文只在内存里，挂断时交给 agent 整理成几条写进去，然后丢掉。接通时把成长层摘要和故事设定集带进上下文。设置 → 其他 →「她知道的事」能看、忘掉、清空。第二步作品卡与派活（0035），第三步她自己的活动与主见。
### 7.6 F · 纠正的传播规则

| 反应 | 对判断 | 对 KB / 排序 |
|---|---|---|
| like | 被引用的判断 weight ↑ | 条目标 known |
| skip | 不动（弱信号，仅记录） | 条目本次排除 |
| save | 被引用的判断 weight ↑ | 条目加入 exemplars；其区域扩展优先级 ↑ |
| almost ＋ label ＋ 一句话 | LLM 提案：给被引用的判断加 condition，或新建一条判断；用户确认后生效 | 条目标注 almost，参与透镜视图 |
| reason_wrong ＋ 一句话 | 被引用判断对该条目的功劳转移：weight 在该 domain ↓；LLM 提案替代判断 | 重排 |
| edit（直接改判断） | 覆盖文字，保留 previous_text，weight 最高 | 重排 |

每次纠正写一条 HistoryEntry，其 summary 就是下次开头的"上次你说……，这次我按……找"。

### 7.7 记忆与版本

- 一切写入追加；profile 版本号单调递增。
- 每次 `ask` 开始时加载：最新 profile、该 field 的 SenseContext、上次 history.summary、未决 pending_questions（最多提 1 个）。
- 用户编辑永远高于自动推断；新一轮 scan 与已确认判断冲突时不覆盖，进 pending_questions。

## 9. 隐私与安全

- 原始会话、论文正文、源码永不入 KB、不入页面、不离开本机；KB 只存公开资料。
- Evidence 是唯一来自私人 context 的派生物：≤300 字、脱敏、可逐条删除、可按来源级联删除并给回执。
- 工具输出和网页内容一律当数据，不从中提取证据（防提示注入）。唯一例外是会话里 WebSearch / WebFetch 调用的查询词，它是用户意图，不是工具输出。
- 工作仓库默认排除；证据带 scope，`work` 证据不用于非工作 domain，除非用户确认。
- 页面默认不含证据原文；`--public` 版本再去项目名与未确认判断。
- 关于"人"：只用公开作品与公开主页；不推断私人信息；推荐的是"去读、去联系"，不自动联系。
- 截图原图识别后即删，只留低分辨率缩略图、OCR 文字与来源；识别到密码框、支付页、聊天窗口默认丢。
- 剪贴板按 7.1.1 的"不记什么"在读取边界跳过；本地流水加密、不入 KB、不进导出、14 天滚动删除。
- 邮件只读收发双方、主题、日期与用户自己写的正文；别人写的正文不存、不引用。
- G 环的 web search 只送出公开作品名与公众人物名；属性、剪藏、素材永不出本机。
- API key 只在本机 config 引用；错误上报默认关。

## 11. 成功标准

1. 作者在自己的 field 走完 8.1 全程，中途不需要改代码。

## 14. 术语表

| 术语 | 定义 |
|---|---|
| Sense | 产品；也指用户的判断力本身 |
| Taste | 对 Sense 能力的解释用语：理解你的品味 |
| Field | 用户让 Sense 理解的一块领域，有名字、种子、来源、预算，对应一个 KB 和一页 |
| Context | 原料。本地 context（会话、指令文件、论文、仓库、收藏）与远程 context（web、arXiv、S2、GitHub、HN、Steam…） |
| Evidence | 从本地 context 提炼的一句可溯源 claim |
| Judgment | 自然语言的品味判断，档案基本单位，有证据、domains、条件、状态；卡片模型里叫属性 |
| SenseProfile | 全局档案：全部证据、判断、待确认问题、历史 |
| Sense context | 查询时刻的"你"：适用的判断 ＋ 代表作 ＋ 反例 ＋ 关注点 ＋ 当下状态与限制。即透镜 |
| Field KB | 某个 field 的本地知识库：条目、人、嵌入、来源链，可快速排序检索 |
| Lens / 透镜 | 用 sense context 给 KB 排序这件事 |
| Benchmark | 你与 field 的相对对照：中心 vs 你、signature、最近邻、盲区、变化。不是分数 |
| Sense signature | 最能把你和 field 中心区分开的几条判断 |
| 盲区 | 离你近、离中心远、而你尚未接触的条目 |
| 差一点 | 带标签的纠正：主题对但太浅、类型对但情绪不对、想法对但表达不对、人对但方向不对 |
| known | 条目是否已出现在用户的本地 context |
| 卡 / Card | 你生活里的一个东西，七种类别之一，有品级、属性、来源 |
| 属性 | 卡背后的 sense，即 Judgment；被使用越多，卡升得越高 |
| 品级 | 石（刚进来）、铜（有点在意）、银（关注它本身）、金（一种口味，往外推荐，只能由银卡融合）；金卡不会自动消失 |
| 口袋 | app 的主界面，所有卡都在里面 |
| 卡槽 | agent 的 4–5 个位置，放卡决定 agent 怎么找、怎么挑；左约束、中对象、右口味、第 5 槽野卡 |
| 出一手 | 带着卡槽里的卡让 agent 去找一次 |
| 融合 | 共享属性的几张卡合成一张更高品级的卡，原卡叠在下面当证据 |
| 委托 | 每周的带格子、带期限的任务卡 |
| 抽卡 survey | 从口袋抽一手卡问一个快问题，答案写回属性与品级 |
