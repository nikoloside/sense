# 0015 · 卡只有两种：判断卡与推荐卡；"待补"是判断卡的状态，不是第三种卡；签名卡退回汇总

日期：2026-10-20 · 状态：**撤回**（2026-10-21，作者否决："不要这个判断"；卡按"是什么"分种类，见 docs/cards-v1.2-proposal.md 第二稿） · 原修订 0013

## 决策
- **判断卡**（显性层）：场 / 选择 / 对照 / 理由 ＋ 证据。四要素齐 = `candidate`，动作是确认 / 不对 / 改一句。缺任一要素 = `pending`（潜在层），卡面照样显示已有要素，缺的那格标"日志里没有"，动作是答一句 / 不是我在意的。答了就升为 candidate。
- **推荐卡**（生成层）：一个具体条目 ＋ 为什么（指向判断卡 id） ＋ 它检验哪几张判断 ＋ 若不喜欢说明哪张判断写错。动作是 like / skip / almost。
- 不再有签名卡。"你和默认做法分岔在哪"是从已确认判断汇总出来的三句话，放在最后的汇总卡上，只看不滑。

## 原因
- 三层是 sense 的状态，不是三种物体：潜在的判断和显性的判断是同一个对象差一两个要素。拆成两种卡会让用户面对两套不同的卡面和动作，而问题只是"缺的那一格"。
- 签名卡是派生物（benchmark），没有可写回的动作，放在滑动流里只会让人问"我要对它做什么"。
- 交互只需要两种反应：对一条判断说对不对，对一个推荐说要不要。多出来的种类不增加能写回的信息。
- 用户 2026-10-20 的原话："签名卡和判断卡和这个潜在卡有点莫名其妙"；"告诉我几个分类到底有什么是必要的，然后可以通过卡的方式来推进交互"。

## 影响
SENSE.md 1.3、7.5；`m0/deck.template.html` 改为两种卡。
