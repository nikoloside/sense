# 0013 · 输出是手机上的一叠卡；MCP 推迟到 v1.1

日期：2026-10-20 · 状态：已定 · 替代 0007 中"三个面"的表述

## 决策
v1 两个面：`sense` CLI 和 `sense render` 生成的卡片页（手机优先的自包含 HTML）。三层各一种卡：潜在卡、判断卡、推荐卡，加一张签名卡；看和纠正是同一个动作。
MCP 不在 v1。进入条件：field 为论文 / 技术且"在终端里临时问一句"成为主要用法；首版只做两个工具：记一笔、读档案。

## 原因
- 把闭环拆成用户在场的六个时刻，前五个 CLI 加卡片页就够；MCP 只在"临时问一句"有价值，而那取决于 field。
- 静态页面无法回写纠正；卡片把看与滑合并，也天然是分享面（0004）。
- 用户 2026-10-20 的原话："mcp 用什么这个不是选择，而是先从体验开始思考是否需要"；"可以有一个手机一堆卡片的 demo"。

## 影响
SENSE.md 5.1、7.5、12、13 调整；第 12 节问题 2、6、8 关闭。
